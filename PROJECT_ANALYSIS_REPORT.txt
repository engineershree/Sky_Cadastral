8. PDF-TO-3D FEASIBILITY & RECOMMENDED PIPELINE
================================================================================

Technical Feasibility Analysis:
  - Scanned cadastral maps and blueprint PDFs vary significantly in resolution, line thickness, rotation, and drawing quality.
  - Fully automated 100% vector conversion without human oversight is technically unreliable for arbitrary real-world land blueprints.
  - A hybrid automated-detection + admin-verification approach is the industry best practice.

Recommended Practical Workflow:

[ 1. UPLOAD ]
  Admin uploads a 2D plot layout PDF or image (PNG/JPG).

[ 2. PROCESS ]
  - Backend or browser client uses `pdfjs-dist` to render the vector/raster PDF to a high-density Canvas image.
  - Image scaling and normalization are applied.

[ 3. DETECT ]
  - Edge & Contour Detection: Thresholding and Canny edge algorithms (via Canvas API or OpenCV.js) detect closed polygon contours.
  - OCR Text Extraction: `tesseract.js` scans bounding boxes inside detected polygons to extract plot numbers automatically.

[ 4. ADMIN REVIEW & CORRECT ]
  - The system overlays detected polygon boundaries and plot numbers over the 2D layout in an interactive 2D canvas editor.
  - Admin reviews detection accuracy, adjusts vertex points if necessary, adds missing plots, deletes noise artifacts, and enters plot details (Area, Price, Facing, Status).

[ 5. GENERATE 3D ]
  - Normalized 2D polygon coordinates `[(x1,y1), (x2,y2)...]` are mapped into 3D world space `[(X1, 0, Z1), (X2, 0, Z2)...]`.
  - 3D Geometry is dynamically constructed using `THREE.ExtrudeGeometry` or `THREE.ShapeGeometry`.

[ 6. PUBLISH ]
  - Admin clicks "Publish 3D Layout".
  - The layout and verified plot geometries become accessible to customers in the 3D Viewer.

11. SECURITY CONSIDERATIONS
================================================================================

Requirements for Future Architecture:
  1. Admin Auth: Enforce JWT authentication with HTTP-only secure cookies and Role-Based Access Control (RBAC) on all `/admin` routes and layout modification APIs.
  2. File Upload Validation:
     - Restrict file uploads strictly to PDF, PNG, and JPEG MIME types.
     - Enforce a 20MB file size limit.
     - Store uploaded files in secure cloud storage buckets (e.g. Supabase Storage / AWS S3) using sanitized file keys.
  3. Concurrent Booking Protection: Database row-level locking or atomic transactions to prevent double-booking race conditions when multiple customers select the same plot.
  4. Input Sanitization: Sanitize customer inquiry forms against XSS and SQL injection.


================================================================================
12. PERFORMANCE CONSIDERATIONS
================================================================================

Future System Performance Mitigation Strategies:
  1. PDF / Image Processing:
     - Render PDF pages in web workers to prevent UI thread blocking.
     - Downsample ultra-high-resolution blueprint images for web preview.
  2. 3D Scene Rendering Optimization:
     - Merged Geometries / Instanced Rendering for repetitive plot elements (trees, boundary posts, roads).
     - Limit dynamic shadow maps and adjust camera shadow frustums.
     - Cap pixel ratio: `Math.min(window.devicePixelRatio, 1.5)` to protect mobile GPUs.
  3. Code Splitting & Lazy Loading:
     - Lazy load heavy 3D components (`@react-three/fiber`) and PDF parsers (`pdfjs-dist`) using React `Suspense` so the initial landing page load time remains sub-second.
