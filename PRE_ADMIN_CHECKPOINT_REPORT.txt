1. INITIAL PROBLEMS FOUND
------------------------------------------------------------
- 3D Pan / Slide Issue: Right-mouse dragging in 3D mode did not slide the camera across the master-plan ground plane. Instead, it moved vertically in screen space or triggered the browser's context menu.
- Label Clutter: 3D scene labels competed for attention when zoomed out, displaying full details everywhere regardless of camera distance.
- 2D Viewport Fill: The 2D SVG map was constrained inside a card box rather than providing a full-bleed interactive map canvas for smooth map travel and cursor-centered zooming.

2. ROOT CAUSE OF 3D PAN ISSUE
------------------------------------------------------------
- Three.js OrbitControls default `screenSpacePanning` was `true`, which pans the camera parallel to the screen plane instead of sliding horizontally across the ground plane `(x, 0, z)`.
- Explicit mouse/touch bindings were missing for `RIGHT: THREE.MOUSE.PAN` and `TWO: THREE.TOUCH.DOLLY_PAN`.
- The canvas container lacked `onContextMenu={(e) => e.preventDefault()}`, allowing browser right-click menus to interrupt smooth dragging.

3. EXACT FIX APPLIED
------------------------------------------------------------
- In `PlotViewer3D.jsx`:
  - Set `screenSpacePanning={false}` on `<OrbitControls>`.
  - Configured `mouseButtons={{ LEFT: THREE.MOUSE.ROTATE, MIDDLE: THREE.MOUSE.DOLLY, RIGHT: THREE.MOUSE.PAN }}`.
  - Configured `touches={{ ONE: THREE.TOUCH.ROTATE, TWO: THREE.TOUCH.DOLLY_PAN }}`.
  - Set `panSpeed={1.2}` and `enablePan={true}`.
  - Added `onContextMenu={(e) => e.preventDefault()}` on the viewport container.
- Right-click dragging now smoothly slides/pans the camera across the 3D master-plan landscape.
